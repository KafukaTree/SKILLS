# Scout 任务书模板(并行调研)

> 用法:复制以下结构,替换 `<<...>>` 占位符。`context` 放公共约束(batch 内所有 scout 共享),`task` 放本 scout 的时段与主题清单。用 `task` 工具一次发出多个 scout;只读调研一律用 `agent: "scout"`。

## context(公共约束,写进 batch context)

```
今天日期: <<YYYY-MM-DD>>。你在为一份中文《<<主题>>节点清单》(<<起>> 至 <<止>>)做事实核查与资料搜集,面向研究者/工程师,强调学术与技术内容:论文、技术报告、架构与算法创新、训练/推理方法、评估基准、开源技术栈。

硬性规则:
1. 聚焦学术与技术。排除一切政经新闻:融资/估值/收购/出口管制/行政令/反垄断/峰会/政策监管/人事新闻。产品发布只在承载技术里程碑时才收录,且描述必须落到技术层面(方法、架构、参数、基准分数),不写营销描述。
2. 每个条目必须给出: 精确日期(年-月-日)、论文/技术报告名或技术事件、一句话技术说明、来源(arXiv ID 或官方技术博客 URL)。
3. 严禁编造或凭记忆填充。你记忆中的论文必须经 web_search 核实 arXiv ID、作者与日期后才能输出; 核实不到的标 [未核实] 并尽量排除。
4. 用 web_search 反复搜索; 冲突时以 arXiv/官方技术文档为准。
5. 输出中文 markdown,按技术主题分组,每条格式: `- **YYYY-MM-DD** 名称: 一句话技术说明 (arXiv:xxxx.xxxxx / URL)`。末尾给"年度技术主线"总结(4-6 条,每条一句话)。
6. 纯调研任务,不要运行任何构建、测试或项目命令。
```

## task(每个 scout 一份)

```
# Target
梳理 <<时间范围,如 2025-01-01 至 2025-12-31>> <<领域>>的学术与技术里程碑,全部条目必须是论文/技术报告/技术方法/基准/开源技术。

# Change(主题清单,逐项搜索核实)
1. <<主题1>>: <<具体候选条目,带我记忆中的 arXiv ID/日期>>
2. <<主题2>>: <<...>>
...
若某个我列出的模型/论文实际不存在或日期不同,以你的核实为准并在输出中注明差异。

# Acceptance
输出中文 markdown 节点清单,按主题分组,每条: 日期+名称+一句话技术说明+来源(完整可点击 URL,arXiv 给 https://arxiv.org/abs/XXXX.XXXXX,官方文档给完整页面 URL;链接必须真实存在,不要拼造)。所有条目必须可溯源; 无法核实的标 [未核实] 并尽量排除。末尾给年度技术主线总结(4-6 条,每条一句话)。
```

## 配套动作

1. **spawn 后检查**:确认任务书完整送达(实战中两次因引号/特殊字符导致主题清单截断,scout 会发 IRC 说"清单截断"——立即 `hub send` 补发完整清单)。
2. **催收尾**(可选):scout 易过度穷尽。`hub send`:"用户催进度,5 分钟内收尾:已核实条目直接输出(不重做),剩余主题快速过一遍,每条保持 日期+名称+一句话+完整链接 格式即可,不必穷尽所有子项。"
3. **输出丢失防护**:scout 可能只回摘要(实战:45 条清单正文丢失)。若发生,`hub send` 让它重发完整内容("你的最终输出只包含摘要,完整清单正文没有传回来,请把完整清单重新输出…");或预先要求它同时写 `local://<name>.md`。
4. **进度查看**:`read history://<agent-id>` 看实时转录(每步工具调用);`hub jobs` 看运行状态;`hub wait` 阻塞等待完成。
